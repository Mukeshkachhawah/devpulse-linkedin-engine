Most people only handle one step in DSA: start coding.

They read the prompt, open the editor, and type. Done.

But that's not what clears interviews.

Every problem actually has five phases:

Clarify — what exactly is asked, and what are the constraints?
Brute — a correct slow solution you can explain
Optimize — the pattern, better complexity, and tradeoffs
Code — clean implementation with clear invariants
Test — edge cases, dry run, complexity restated

Skip the first three, and the interviewer starts inventing their own story.

You missed empty input.
You missed n = 10^5.
You wrote clever code for the wrong problem.

Before I write a single line, I ask myself:

- Can I restate the problem in one sentence?
- What is the brute-force approach and its complexity?
- Why is brute not enough for these constraints?
- Which edges will break my first idea?

DSA is not just getting the accepted green check.

It's showing a repeatable path so your thinking still feels honest under pressure.
